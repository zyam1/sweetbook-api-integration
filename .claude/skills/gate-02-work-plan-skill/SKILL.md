# Gate 2: 작업계획서 작성 + 승인

> **핵심**: Gate 1 분석 결과를 작업계획서로 정리 → 사용자 명시적 승인 후 Gate 3 진입

---

## 0. INVIOLABLE RULES

| # | 규칙 | 위반 시 |
|:-:|------|--------|
| 1 | 본 SKILL Read 필수 | **진입 무효** |
| 2 | Gate 1 분석 결과 + 영향 범위를 작업계획서에 모두 포함 | **계획 무효** |
| 3 | 변경 파일 목록 누락 금지 (신규/수정 구분) | **계획 무효** |
| 4 | 사용자 "승인/진행/1번" 등 명시적 표현 없이 Gate 3 진입 금지 | **작업 무효** |
| 5 | "좋아/OK/응" = 무효 → 선택지 재제공 |  |

---

## 1. 작업계획서 필수 항목

| 항목 | 설명 |
|------|------|
| **목표** | 무엇을 왜 하는지 1~2줄 |
| **변경 파일 목록** | 신규 생성 / 수정 구분, backend↔frontend 분리 |
| **구현 방법** | 각 파일별 핵심 변경 내용 |
| **API 호출 순서** | SweetBook API 1~10 중 어떤 단계 사용하는지 |
| **위임 에이전트** | CLAUDE.md 5.2절 매핑표 기준, 파일별 담당 에이전트 |
| **영향 범위** | backend↔frontend 동기화 필요 항목 |
| **위험 요소** | 예상되는 실패 지점 / 주의사항 |
| **검증 방법** | 작업 완료 후 어떻게 확인할지 |

---

## 2. 수행 절차

| 순서 | 절차 |
|:----:|------|
| 1 | 본 SKILL Read |
| 2 | Gate 1 분석 결과를 위 8개 항목으로 정리 |
| 3 | 작업계획서 응답으로 출력 (파일로 저장하지 않음, 대화로만) |
| 4 | 선택지 3개 제공: 승인 / 수정 요청 / 취소 |
| 5 | 사용자 명시적 선택 수신 |

---

## 3. 선택지 (3개, 한 글자도 수정 금지)

| 번호 | 선택지 | 다음 |
|:----:|--------|------|
| 1 | **승인 — 계획대로 진행** | Gate 3 진입, gate-03-execute-skill 호출 |
| 2 | **수정 요청** | 계획 수정 후 재제시 (Gate 2 반복) |
| 3 | **취소 → Gate 1 복귀** | Gate 1 재진입 |
