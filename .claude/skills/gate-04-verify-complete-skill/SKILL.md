# Gate 4: 검증 + 동기화 + 완료 보고

> **핵심**: CLAUDE.md ## 2.3 5단계 최종 검증 + 동기화 완전성 확인 + 사용자 테스트 안내

---

## 0. INVIOLABLE RULES

| # | 규칙 | 위반 시 |
|:-:|------|--------|
| 1 | 본 SKILL Read 필수 | **진입 무효** |
| 2 | 5단계 검증 1개라도 미충족 = 응답 금지, Gate 3 복귀 후 재작업 | **검증 무효** |
| 3 | 동기화 미수행 변경 = 해당 변경 무효 (CLAUDE.md ## 7) | **작업 무효** |
| 4 | 사용자에게 테스트 방법 안내 누락 금지 |  |

---

## 1. 5단계 최종 검증 (CLAUDE.md ## 2.3)

| # | 검증 항목 | 미충족 시 |
|:-:|----------|----------|
| 1 | **구조 파악**: 기존 코드 패턴/흐름 일관성 | 대상 파일 재확인 |
| 2 | **문서 확인**: 관련 .claude/ 문서 근거 존재 | 문서 Read |
| 3 | **안전성**: API 키 노출, 보안 문제 없음 | 즉시 수정 |
| 4 | **파급 영향**: backend↔frontend, 다른 service 영향 처리 | 영향 파일 확인 |
| 5 | **API 순서**: SweetBook API 호출 순서 준수 | 순서 재확인 |

---

## 2. 동기화 검증 (CLAUDE.md ## 7)

| 유형 | 트리거 | 확인 항목 |
|:----:|--------|----------|
| **A** | backend 코드 수정 | 대응 frontend feature 동기화 여부 |
| **B** | frontend 코드 수정 | 대응 backend route/service 일치 여부 |
| **C** | 새 도메인 추가 | backend(route+service) + frontend(feature) 동시 생성 여부 |
| **D** | API 엔드포인트 변경 | backend route + frontend API 호출부 + .claude/ 문서 일치 여부 |

---

## 3. 수행 절차

| 순서 | 절차 |
|:----:|------|
| 1 | 본 SKILL Read |
| 2 | Gate 3 작업 결과 + 변경 파일 목록 확인 |
| 3 | 5단계 검증 항목별 통과/미통과 판정 |
| 4 | 동기화 유형 식별 (A/B/C/D) + 동기화 완료 여부 확인 |
| 5 | 미통과 항목 존재 시 → Gate 3 복귀 + 재작업 지시 |
| 6 | 모두 통과 시 → 완료 보고 작성 |
| 7 | 사용자에게 테스트 방법 안내 |
| 8 | 통과 선언 |
