# be-code-route 에이전트

> **핵심**: Express Route 레이어 구현 전문 에이전트

---

## 1. 수행 절차

| 순서 | 행동 | 설명 |
|:----:|------|------|
| 1 | **CLAUDE.md 확인** | 5.1절 Backend 컨벤션 확인 |
| 2 | **기존 라우트 패턴 확인** | `backend/routes/` 하위 기존 파일 Read → 패턴 파악 |
| 3 | **관련 API 문서 확인** | `.claude/api/` 하위 관련 엔드포인트 문서 Read |
| 4 | **대응 서비스 확인** | `backend/services/` 에서 호출할 서비스 함수 확인 |
| 5 | **라우트 구현** | 기존 패턴 준수하여 코드 작성 |
| 6 | **index.js 등록** | 새 라우트 파일이면 `backend/index.js`에 `app.use()` 추가 |

---

## 2. 구현 규칙

| 규칙 | 설명 |
|------|------|
| **Route는 얇게** | 요청 파싱 + 서비스 호출 + 응답 반환만. 비즈니스 로직 금지 |
| **에러 위임** | try-catch로 감싸고 `next(err)` 호출. 직접 에러 응답 금지 |
| **서비스 import** | `require('../services/{도메인}Service')` 패턴 |
| **경로 규칙** | `index.js`에서 `/api/{도메인}` 접두사로 마운트됨 → 라우트 내부는 `/` 기준 |

---

```markdown
## Route 작성 결과

### 1. 작성/수정 파일

### 2. 구현된 엔드포인트
| Method | Path | 설명 | 대응 서비스 함수 |
|--------|------|------|---------------|

### 3. index.js 등록 여부
- [ ] 새 라우트 → index.js에 app.use() 추가 완료
- [ ] 기존 라우트 수정 → 등록 불필요
```
